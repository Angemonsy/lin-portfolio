# Alpha Rebirth 隐藏副本

该目录是线上私人 Alpha Rebirth 界面。原有打卡、双侧图片栏、登录、PWA 和数据同步继续保留。完整知识库工作台在本地运行，云端通过模式 B 提供状态感知与回跳。

## 模式 B：本地工作台入口

- 登录成功后，桌面浏览器向 `http://127.0.0.1:5174/` 发起一次 `HEAD`、`no-cors` 探测，最多等待 1.5 秒，不发送凭据、不读取正文、不使用缓存。
- 可达时显示绿色「进入本地知识库工作台」，在新标签打开 `http://127.0.0.1:5174/?v=19.1&view=workbench`。`view=workbench` 用于直接打开工作台。
- 手机和平板跳过探测，显示「云端便携模式」。桌面探测失败也显示此状态，并提供重新检测和手动打开入口。
- 返回页面时可重新检测，两次自动检测至少间隔 30 秒；不持续轮询。退出登录后停止探测。
- HTTPS 到本机 HTTP 的请求可能受浏览器本地网络策略限制，因此无法保证所有浏览器都能自动识别；失败不等于服务一定离线。无需关闭浏览器安全保护，可直接打开本地入口。
- 心跳只证明端口可达，不能认证其服务身份。进入本地后仍使用本地原有登录；云端令牌不会随跳转传递。
- Service Worker 不拦截跨域请求，避免缓存心跳造成假在线。

## 云端记录接续到本地

1. 手机或电脑完成云端打卡，等待显示「已保存」。
2. 在 Mac 打开本地工作台，点击已有的「从云端接续」。
3. 首次连接输入云端账户，再点击「读取并合并最新记录」。存在冲突时选择保留本地或采用云端。

此按钮由本地应用现有的认证接口提供，只接续打卡、任务、留痕和复盘，并保留冲突检查及备份。本地修改暂不回传云端；知识库正文、附件和文件路径不参与。此流程不同于下文的脱敏经营快照上传。

## 验证模式 B

在仓库根目录运行：

```bash
node --check alphakk999/local-workspace.js
node --test alphakk999/local-workspace.test.cjs
git diff --check -- alphakk999
```

浏览器检查：未登录不探测；本机服务可达时显示绿色入口；服务停止或请求被阻止时显示便携模式；重新启动服务后可以重新检测。手机 390px 布局不应自动探测或显示本地跳转链接，打卡仍可保存。部署后需在实际 HTTPS 域名和常用浏览器中再检查本地网络权限行为。

## 数据边界

- GitHub 只保存页面和 Edge Function 代码。
- 完整 Markdown、目录、附件、路径、Wiki 双链和搜索索引留在本机。
- 云端继续保存原有账号打卡数据；知识库相关上传仅允许 `alpha-rebirth-cloud-package/v1` 脱敏经营快照。
- 工作台必须登录后访问，页面继续使用 `noindex` 与 `no-store`。

## 接口

`/api/a8-knowledge`：

- `GET`：需要 Alpha 登录会话，读取当前私人经营快照。
- `PUT`：接受 Alpha 登录会话，或专用同步令牌。
- 最大请求体 `100 KB`。
- 服务端重新校验 Schema、隐私声明、禁用字段、体积和 SHA-256 摘要。
- 新版本写入前保留上一版 KV 记录。

自动推送需要在 EdgeOne 配置：

```text
ALPHA_CLOUD_SYNC_TOKEN_HASH=<专用同步令牌的 SHA-256>
```

本地 Alpha 配置同一令牌的明文 `ALPHA_CLOUD_SYNC_TOKEN`，不得将明文提交到 GitHub。

## 原有脱敏快照上传接口

本地生成脱敏 JSON：

```bash
npm run cloud:export
```

`workspace-cloud.js` 保留原有快照浏览与导入实现；当前打卡首页不挂载完整云端工作台。`/api/a8-knowledge` 的脱敏快照上传与模式 B 无关，本次不新增接收端，也不运行 `npm run cloud:push`。
